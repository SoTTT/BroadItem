# BroadItem 生态位定位与设计调整计划

> 本文是 BroadItem 项目的定位结论与对应的设计调整工作清单，作为后续实施工作的基准文档。
> 架构规格仍以《设计.md》为准；本文中的调整项落地后，应回写《设计.md》。

## 一、生态位定位

> **BroadItem 不是 QML 的穷人版，而是 QGraphicsView 世界的 QML——它服务的不是"正在选择技术栈的新项目"，而是"已经被技术栈选择、还要再活十五年的老项目"。**

一句话定位：**给"已经被锁在 QGraphicsView 里的既有应用"提供数据驱动的场景内信息标牌。** 在这条缝里，QML 进不来（scene graph 与 GraphicsView 互不嵌套），HTML 不让进（工业保守环境禁止 JS 引擎），ProxyWidget 不好用（缩放失真、交互开销），手写 `paint()` 不划算（标牌变体 ≥5 种后边际成本线性增长）。

典型决定性瞬间：存量工业 Qt 项目（电网监控、电力仿真、网络拓扑）需为场景内数百个图元追加数据驱动的状态铭牌，数据秒级刷新，样式由现场实施人员调整且不允许重新发版。

生存策略对标 Qwt：窄而可守，零依赖、静态库、可整体 vendor、全部源码可审计——小而乏味是采购加分项，需在架构上自觉守护。

## 二、设计调整清单

### P0：核心表达能力（让铭牌场景"能交付"）

| # | 调整项 | 内容 | 服务的场景 |
|---|--------|------|-----------|
| P0-1 | 绑定通用化 ✅ 已完成（ab98533 feat(binding) + 后续 test/docs 提交） | `b:` 前缀引用语义从 `content`/`of`/`prop` 三个绑定点推广到**全部字面量属性**（如 `b:color`、`b:background-color`）。统一走"字面量 \| 绑定"二分解析，沿用互斥规则与前缀匹配通知机制 | 报警变色、主题换肤（全局上下文放颜色变量即实现换肤，样式复用需求随之降级） |

## 三、设计护栏（明确不改）

| 现有决策 | 守护理由 |
|---|---|
| 无自上而下约束、内容驱动尺寸 | GraphicsView 浮动图元的正确模型 |
| 不支持指定容器大小 | 刻意的语义收窄，《设计.md》已论证 |
| 控制元素透明展平 | 心智模型极简，工具链可静态推导 |
| 无交互、无动画、无脚本 | 性能、可审计性、与 ProxyWidget 边界的三重来源 |
| 纯 Qt 类型、零第三方依赖 | 保守环境采购的通行证 |
| 响应式模块保持 C++ API，不进 XML | "买标牌送连线"的附属能力；进 XML 会产生第二个模板语义层，复杂度失控 |

## 四、回写约定

每项调整落地时：

1. 更新《设计.md》对应章节，保持"文档即规格"的现状；
2. 补充对应测试套件（沿用 `Test*` + `QTEST_MAIN` 约定）；
3. XML 语法变化同步更新 `broaditem.xsd`。
