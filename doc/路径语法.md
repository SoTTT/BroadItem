# 路径语法专项设计

> 2026-08 定稿。绑定路径（`b:content="device.cpu"`、`items[0].name` 等）的语法规范与实现设计。
> 本文是语法的**唯一书面规范**；实现的唯一权威是 `Expression`（`include/broaditem/expression/Expression.h`）。
> 缘起与历史分歧证据见 `doc/土法编程审阅.md` #1（附 #14）。

## 1. 语法规范

### 1.1 形式定义

```
path      := keyPart indexPart* ( "." keyPart indexPart* )*
keyPart   := identStart identContinue*
identStart:= Unicode 字母（含中文等）| "_"
identContinue := Unicode 字母 | Unicode 数字 | "_"
indexPart := "[" int "]"        -- int 经 QString::toInt 解析，须成功且 ≥ 0
```

约束（任意一条违反即整个路径非法）：

1. 路径不得为空；
2. 键分段必须是 Unicode 标识符（规则见上）——排除空键、数字开头、
   连字符/空格/特殊字符键（真实非 ASCII 数据键如 `设备` 合法）；
3. `[` 必须紧跟键分段或 `]`（即允许 `a[0][1]` 连续索引）；
4. `[` 必须闭合，索引必须为非负整数（`QString::toInt` 语义：容忍首尾空白与前导正号，`a[ 5 ]`、`a[+5]` 合法——此为有意保留的宽松点，见 §4）；
5. `]` 之后只允许 `.`、`[` 或结尾；
6. 不得以 `.` 结尾。

### 1.2 合法 / 非法示例表

| 路径 | 判定 | 说明 |
|------|------|------|
| `name` | ✅ | 单键 |
| `device.cpu` | ✅ | 典型嵌套 |
| `items[0].name` | ✅ | 索引 + 键混合 |
| `a[0][1].c` | ✅ | 连续索引 |
| `_private`、`a1`、`设备.cpu` | ✅ | 下划线开头 / 含数字 / Unicode 键 |
| `a[ 5 ]`、`a[+5]` | ✅ | toInt 宽松点（§4） |
| `""` | ❌ | 空路径 |
| `123`、`1abc`、`a.2024.b` | ❌ | 数字开头（2026-08 收紧，§3.1） |
| `a-b`、`a b`、`a]b` | ❌ | 键含非法字符（2026-08 收紧，§3.1） |
| `.a`、`a..b` | ❌ | 空键分段 |
| `[0].a`、`a.[0]` | ❌ | `[` 未紧跟键 |
| `a[0`、`a[b]`、`a[-1]` | ❌ | 未闭合 / 非整数 / 负索引 |
| `a[0]b` | ❌ | `]` 后裸键（历史分歧点，§3） |
| `a.`、`a[0].` | ❌ | 结尾点号（历史分歧点，§3） |

### 1.3 分段中间表示（IR）

解析产物为类型化分段序列，是语法与遍历之间**唯一**的中间表示。
`PathSegment` 是键 | 索引的**真和类型**：存储为 `Variant<QString, int>`
（vendored mpark/variant），非法组合状态物理上不存在，
仅能通过 `makeKey`/`makeIndex` 工厂构造：

```cpp
class PathSegment {
public:
    static PathSegment makeKey(const QString& k);
    static PathSegment makeIndex(int i);
    bool isIndex() const;
    const QString& key() const;  // 仅键分段（错误分支抛 bad_variant_access）
    int index() const;           // 仅索引分段（同上）
};
```

`items[0].name` → `[key:items, index:0, key:name]`。语法保证首段必为键分段。

## 2. 代码设计

### 2.1 单一权威原则

- **语法只在 `Expression` 定义一次**（解析期校验 + 产出 IR）。
- 运行期遍历（`PropertyContext`）**不解释路径字符串**，只消费 `PathSegment` 序列；
  入口（`MapPropertyContext` / `QPropertyContext` / `walkPathFromObject`）先经
  `Expression` 解析，非法路径统一报 BI-R-005（PathSyntaxError）。
- 前缀匹配语义唯一实现在 `Expression::pathMatches()`，
  `Element::matchesProperty` 与 `Binding::bindsProperty` 均为委托。

### 2.2 模块与依赖

- IR（`PathSegment`）与解析器同在 `expression/` 模块；
- `context/` → `expression/` 单向依赖（`PropertyContext.h` 包含 `Expression.h`），无环；
- 遍引擎收敛为两个函数，均在 `src/context/PropertyContext.cpp`：
  - `walkSegments(current, segs, start, path)`：读，逐段类型断言（map/list）与存在性检查；
  - `setWalkSegments(current, segs, start, path, value)`：写，递归下沉、叶子写值、逐层回写，失败无副作用。

### 2.3 不变量

- 诊断错误码与消息文案不变（BI-R-001~005 的触发条件与措辞保持原样）；
- 首段解析职责仍在各入口（map 查找 / `QObject::property()`），walker 只处理 `segs[1:]`；
- 静默清单不变：`MapPropertyContext` 首段未注入仍静默返回无效值；
- `Binding`/`Element` 公共 API 不变（`matchesProperty` 保留为委托）。

### 2.4 删除项

`segmentEnd`、`advanceBrackets`、`walkNested`、`setWalkInto` 及三处逐字重复的 `[n]` 处理块（约 90 行游标逻辑）。

## 3. 历史分歧点裁决

统一前两套实现（解析期 `Expression` vs 运行期 walker）在两个边角输入上判定相反，本次裁决均取"非法"：

| 输入 | 旧：解析期 | 旧：运行期 | 新（统一后） | 裁决理由 |
|------|-----------|-----------|-------------|----------|
| `a.`、`a[0].` | 非法 | **静默接受** | 非法 | 结尾点号几乎必为笔误；接受会掩盖书写错误 |
| `a[0]b` | **合法**（分段 [a,0,b]） | 必报 BI-R-005 | 非法 | `]` 后裸键无语义，旧解析期的"合法"本身即是 bug |

行为影响面：仅病态输入；合法路径语义零变化（双栈 ctest 18/18 + 金图逐像素比对通过）。

### 3.1 键标识符收紧（2026-08，交互验证发现）

问题：旧规则下键分段是"非分隔符任意字符"，`123`、`1abc`、`a.2024.b` 均合法——违背常见语言的标识符直觉；QObject 属性名本就必须是 C++ 标识符，宽松规则对 QObject 侧是虚假承诺。

裁决（选项 B）：键收紧为 **Unicode 标识符**（首字符字母或 `_`，后续允许字母/数字/`_`），
而非严格 ASCII 标识符——后者会把 `设备.cpu` 这类真实数据键挡在门外，属于行为断代。
连字符/空格/`]` 等特殊字符键随之非法（本属坏味道）。

## 4. 已知宽松点（有意保留）

- 索引经 `QString::toInt` 解析，容忍空白与前导正号（`a[ 5 ]`、`a[+5]`）。
  两侧历史实现一致地宽松，收紧属于语法变更而非修复，如需收紧应单独立项并同步本节。
