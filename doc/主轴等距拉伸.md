# BroadItem 主轴等距拉伸（main-stretch）设计说明

## 一、设计动机

BroadItem 当前的 `SizedElement` 只支持 `width` / `height` 两种尺寸模式：

- **完全自动**：尺寸由内容决定。
- **完全固定**：用户显式写一个像素值。

在真实标牌场景中，这两种模式都不够用。例如一个工具栏：

```xml
<row>
  <text>OK</text>
  <text>Cancel</text>
  <text>Apply</text>
</row>
```

三个按钮的文本长度不同，自动宽度下会宽窄不一，视觉不整齐。用户希望它们**等宽**，但又不想手动指定 `width="80"` 这种硬编码值——因为内容可能变化，硬编码既不灵活也破坏自适应。

现有的 `cross-align="stretch"` 只能统一交叉轴尺寸：

- 在 `<row>` 中：只能统一**高度**，不能统一**宽度**。
- 在 `<column>` 中：只能统一**宽度**，不能统一**高度**。

因此需要一个新的机制，让容器在**主轴方向**上统一子元素尺寸，使视觉宽度或高度一致。

## 二、取舍过程

### 方案对比

| 方案 | 是否需要指定像素 | 是否破坏自下而上 | 说明 |
|---|---|---|---|
| `min-width` / `max-width` | 是 | 否 | 给动态内容加硬边界，但不能实现“等宽” |
| `main-align="stretch"` | 否 | 否 | 把拉伸语义合并进主轴对齐属性 |
| 新增独立属性 `main-stretch` | 否 | 否 | 与 `main-align` 正交，可组合 |

### 为什么不选 `min/max-*`

`min/max-*` 解决的是“动态内容不能超过某个边界”的问题，属于**安全围栏**。它不能实现“让子元素按内容最大值彼此对齐”的效果。如果用户想要等宽，仍然需要手动指定像素值，不符合“尽量避免硬编码尺寸”的诉求。

### 为什么不把 `stretch` 放进 `main-align`

`main-align` 当前语义是“主轴剩余空间分配”：`start`、`center`、`end`、`space-between`、`space-around`、`space-evenly`。

如果新增 `main-align="stretch"`，会产生两个问题：

1. **语义混淆**：`space-*` 是在总尺寸已经确定后分配空隙；而 `stretch` 会先改变每个子元素的尺寸，从而改变总尺寸。
2. **无法组合**：用户可能想要“等宽后再居中”。合并后无法表达 `main-align="stretch center"` 这样的组合。

因此选择新增一个独立布尔属性 `main-stretch`，与 `main-align` 正交。

## 三、设计原则

1. **自下而上是底线**
   - 容器总尺寸仍由子元素内容决定。
   - 不允许容器显式指定宽高，也不引入百分比等依赖父尺寸的语义。

2. **尽量不给用户增加心智负担**
   - 用户不需要指定像素值。
   - 默认行为不变：`main-stretch` 不开启时，行为与现在完全一致。

3. **尊重显式意图**
   - 显式设置了 `width` / `height` 的子元素不参与拉伸，但仍然参与“最大值”计算。
   - 这与现有 `cross-align="stretch"` 的行为一致。

4. **正交组合**
   - `main-stretch` 只控制主轴方向的尺寸统一。
   - `cross-align` 仍然控制交叉轴对齐/拉伸。
   - `main-align` 仍然控制主轴剩余空间分配。
   - 三者可以独立使用，也可以组合使用。

## 四、最终方案

### 4.1 新增 XML 属性

```xml
<row main-stretch="true">
  <text>A</text>
  <text>BBB</text>
  <text>CC</text>
</row>
```

- 属性名：`main-stretch`
- 类型：布尔（`true` / `false`）
- 默认值：`false`
- 适用元素：`<row>`、`<column>`

### 4.2 行为定义

#### `<row>` 开启 `main-stretch`

- 所有子元素的主轴尺寸统一为“最宽子元素的宽度”。
- 主轴方向即水平方向。
- 显式设置 `width` 的子元素：自身不被拉伸，但参与最大值计算。
- 布局总宽度 = `maxWidth × count + space × (count - 1)`。

#### `<column>` 开启 `main-stretch`

- 所有子元素的主轴尺寸统一为“最高子元素的高度”。
- 主轴方向即垂直方向。
- 显式设置 `height` 的子元素：自身不被拉伸，但参与最大值计算。
- 布局总高度 = `maxHeight × count + space × (count - 1)`。

### 4.3 实现要点

#### 测量阶段

1. 正常测量每个子元素的主轴尺寸。
2. 取最大值 `maxMainSize`。
3. 容器总尺寸按 `maxMainSize × count + space × (count - 1)` 计算。

#### 布局阶段

1. 用 `maxMainSize` 作为每个子元素的主轴约束，**重新 measure 一次**。
   - 这对 `<text wrap="true">` 尤其重要：宽度从 40 拉到 150 后，换行行为会变化，高度也会变化。
2. 根据新的测量结果进行定位。
3. 子元素内部的内容对齐仍由子元素自身的 `h-align` / `v-align` 控制。

## 五、与 `main-align` 的关系

### 5.1 根元素场景

作为根元素时：

```xml
<row main-stretch="true">
  <text>A</text>
  <text>BBB</text>
</row>
```

容器总宽度 = 子元素等宽后的宽度之和 + 间距。主轴方向上**没有剩余空间**。

因此在这个场景下，`main-align` 不生效。

### 5.2 嵌套场景

`main-align` 的意义在于**容器被父元素在交叉轴上拉伸后，主轴出现剩余空间**。

根据设计文档：

> 当行作为列（`<column>`）的直接子部件时，其宽度会被拉伸至该列中所有直接子部件的最大宽度。

示例：

```xml
<column cross-align="stretch">
  <row main-stretch="true">
    <text>A</text>
    <text>BBB</text>
  </row>
  <row>
    <text>很长一段文本</text>
  </row>
</column>
```

- 第一行 `main-stretch`：内部两个 text 等宽，按 "BBB" 的宽度拉齐。
- 第二行更宽，决定列宽。
- 第一行被父 column 拉伸到列宽，内部出现剩余空间。

此时再配 `main-align="center"`：

```xml
<column cross-align="stretch">
  <row main-stretch="true" main-align="center">
    <text>A</text>
    <text>BBB</text>
  </row>
  <row>
    <text>很长一段文本</text>
  </row>
</column>
```

效果：第一行内部等宽后，再把这一行作为一个整体在列宽内居中。

### 5.3 结论

| 属性 | 作用 |
|---|---|
| `main-stretch` | 统一子元素的主轴尺寸 |
| `main-align` | 分配主轴上的剩余空间 |
| `cross-align` | 分配/拉伸交叉轴尺寸 |

`main-stretch` 和 `main-align` 的组合价值，主要体现在**嵌套场景**。单独的 `main-stretch` 已经能解决工具栏按钮等宽等常见问题。

## 六、注意事项

### 6.1 与 `cross-align="stretch"` 的关系

- `cross-stretch` 拉伸交叉轴尺寸，不改变容器总尺寸的计算方式。
- `main-stretch` 拉伸主轴尺寸，会改变容器总尺寸。
- 两者正交，可同时开启。

### 6.2 与显式 `width` / `height` 的优先级

- 显式尺寸不参与拉伸。
- 但显式尺寸参与最大值计算。
- 如果所有子元素都显式指定了主轴尺寸，`main-stretch` 仍然有效——它会统一其他子元素，但显式指定的保持原样。

### 6.3 与 `min-width` / `max-width` 的潜在配合

未来如果引入 `min/max-*`，二者应自然配合：

```xml
<row main-stretch="true">
  <text max-width="120">很长很长的动态内容</text>
  <text>短</text>
</row>
```

- 第一个 text 被 `max-width` 限制在 120。
- `main-stretch` 的最大值计算基于 120。
- 第二个 text 也被拉伸到 120。

`max-*` 可作为 `main-stretch` 的安全边界，避免某个子元素内容过长把其他子元素拉得过宽。

### 6.4 对 `<grid>` 的影响

当前未计划让 `<grid>` 支持 `main-stretch`。Grid 的单元格尺寸已经由列宽/行高决定，逻辑不同。如果未来有“按列统一单元格宽度”等需求，可单独设计。

### 6.5 诊断与错误处理

- `main-stretch` 解析失败或非法取值时，按默认 `false` 处理并输出 `qWarning`。
- 子元素 measure 失败时，不参与最大值计算。

## 七、小结

| 项目 | 结论 |
|---|---|
| 动机 | 让容器在主轴方向统一子元素尺寸，实现等宽/等高，避免硬编码像素 |
| 原则 | 自下而上、尊重显式意图、正交组合 |
| 方案 | 新增独立布尔属性 `main-stretch`，不修改 `main-align` 语义 |
| 关键实现 | measure 时取最大值，layout 时用最大值重新约束子元素再测量 |
| 与 `main-align` 关系 | `main-stretch` 负责尺寸统一；`main-align` 负责剩余空间分配；后者只在容器被父元素拉伸时才生效 |
| 后续配合 | 未来可与 `min/max-*` 结合，作为安全边界 |
