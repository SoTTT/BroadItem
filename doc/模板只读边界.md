# 模板只读边界专项设计

> 2026-08 定稿并已实施（双栈 ctest 18/18 + 负测试验证编译期闭合）。缘起 `doc/土法编程审阅.md` #5。
> 目标：把"模板树不可变"从注释约定升级为类型系统强制——共享边界一律
> `shared_ptr<const Element>`，下游从类型上拿不到任何 mutator。

## 1. 问题（现状证据）

- 约定仅存在于注释（`Element.h:36-38`："Element 树在 parse 后不可变，可安全共享"）；
- 共享路径全程可变指针：`LayoutRegistry::getLayout` 返回 `shared_ptr<Element>`、
  `Frame::m_rootTemplate` 同（注释写"不可变"，类型不写）；
- 可变入口全 public：`parse()`、`addParsedChild()`、`addChild()`、`setContent()`、
  `ForElement::setTemplate()` 等；
- 失效场景：下游 `getLayout(id)` 后调 `addChild()`/再 `parse()` → 所有共享该模板的
  Frame 行为静默改变，且已物化 Node 树与模板错位，零防护。

**有利事实**：管线从不合法修改模板——`Node::element` 已是 `const Element*`，
`materialize/measure/layout/render` 全为 const 方法；可变方法的唯一合法调用方是
解析期的 `XmlLayoutParser`。const 化因此只是"把事实写进类型"。

## 2. 设计

### 2.1 新别名（`include/broaditem/element/Element.h`）

```cpp
class Element;
using ElementPtr = std::shared_ptr<Element>;
/// @brief 共享模板的只读句柄：注册表/Frame/布局引擎等共享边界一律使用本类型。
/// 构建期（XmlLayoutParser）使用 ElementPtr，交付共享时隐式转换为本类型。
using ConstElementPtr = std::shared_ptr<const Element>;
```

### 2.2 边界签名变更（全部改动点）

| 位置 | 现状 | 改为 |
|------|------|------|
| `LayoutRegistry::registerLayout` | `(int, const ElementPtr&)` | `(int, const ConstElementPtr&)` |
| `LayoutRegistry::getLayout` | `ElementPtr` | `ConstElementPtr` |
| `LayoutRegistry::m_layouts` | `QMap<int, ElementPtr>` | `QMap<int, ConstElementPtr>` |
| `Frame::m_rootTemplate` | `ElementPtr` | `ConstElementPtr` |
| `LayoutEngine::materialize` | `(const ElementPtr&, ...)` | `(const ConstElementPtr&, ...)` |

parser 侧（`parseFile`/`parseString`/`parseNode`/`createElement`）**保持 ElementPtr
不变**——构建期需要可变树；交付边界（`registerLayout` 调用、`Frame` 赋值、
`LayoutEngine::materialize` 调用）依赖 `shared_ptr<Element>` → `shared_ptr<const Element>`
的标准隐式转换，调用点零改动。

### 2.3 明确不动的部分

- **模板树内部链接**：`MultiChildContainer::m_children`、`ContainerElement::m_content`
  等仍为 `ElementPtr`（构建期可变是必需）；
- **树内访问器**：`GridLayout::children()`、`ContainerElement::content()` 等返回类型不变——
  全库无外部调用方（已 grep 确认），经 getLayout 取得 const 根的下游够不到这些访问器
  （`const Element*` 上调不了非 const 方法）。这是有意的残留面，注释声明即可；
- `BroadItem` 公共 API（不暴露 ElementPtr，无需改动）；
- 解析期挂载协议（`addParsedChild`/`validateChildren`）保持 public——parser 经可变指针调用。

### 2.4 别名去重（顺手收口）

`using ElementPtr = std::shared_ptr<Element>;` 目前在 4 个头文件重复定义
（Element.h、LayoutEngine.h、LayoutRegistry.h、XmlLayoutParser.h）。
`ConstElementPtr` 只在 `Element.h` 定义，其余头文件包含 Element.h 使用；
存量重复别名本轮不动（ODR 无害，另见收口机会）。

## 3. 行为不变量

- 纯类型层面改动，零运行时行为变化；
- 调用方兼容：`shared_ptr<Element>` 到 `shared_ptr<const Element>` 隐式转换覆盖全部
  现有调用点（测试直接 `LayoutEngine::materialize(parse(...), ctx)` 无需改）；
- 诊断、金图、API 语义全不变。

## 4. 验证方式

- 双栈构建 + ctest 18/18；
- 编译期验证（负测试）：在临时 scratch 文件中写
  `LayoutRegistry::instance().getLayout(0)->parse(dom)` 之类调用，确认**编译失败**，
  验证后删除——证明边界真的闭合。

## 5. 测试锚点

- 现有全量套件即回归网；
- 负测试以编译失败形式存在，不进测试套件（§4 一次性验证）。
